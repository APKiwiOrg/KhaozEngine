# KhaozEngine.Input 0.2.0 — multi-touch, controller cursor, middle/right mouse

**Date:** 2026-06-08
**Status:** Approved (pending written-spec review)
**Baseline:** 0.1.3

## Goal

Close the three `KhaozEngine.Input` gaps SpaceGame surfaced during its migration, so it can drop
its game-side shims and re-enable mobile dual-stick touch and true pinch. All additions are to
`KhaozEngine.Input`, all headless-testable, and **purely additive** — Hardpoint and Nullwake keep
compiling and behaving identically without changing a line.

## Background

The single-pointer `InputManager` forced SpaceGame to keep three shims (documented in its
`docs/khaozengine-integration.md`): a game-side `VirtualCursor`, a hand-rolled middle-click edge,
and single-pointer pinch/dual-stick approximations. The last one left **mobile dual-stick touch
disabled** and SpaceForge pinch-zoom approximated. Folding these into the engine removes the
duplication and is best done before SpaceGame's screen migration (Phase 2) so that phase can assume
them.

## Decisions

Settled during brainstorming:

1. Ship all three additions in 0.2.0.
2. Fold the controller cursor into the engine (not left game-side), accepting an optional `dt`
   parameter on `Update`.
3. Everything additive: optional parameters and new members only; no breaking changes.

## Additions

### 1. Middle / right mouse button edges

`RawInputState` already carries `MouseMiddleDown` / `MouseRightDown`; `InputManager` simply does not
track them frame-to-frame. Track previous/current for both and expose, mirroring the left-pointer
gating (`isActive` + in-window, desktop only — false on mobile):

- `bool IsMiddleDown`, `bool IsMiddleJustPressed`, `bool IsMiddleJustReleased`
- `bool IsRightDown`, `bool IsRightJustPressed`, `bool IsRightJustReleased`

SpaceGame's "middle-click selects the focused entry" becomes `IsMiddleJustReleased`.

### 2. Multi-touch surfacing + richer pinch

- **`TouchPoint` gains an optional `int Id = 0`** as the last positional record parameter, so
  existing `new TouchPoint(position, state)` call sites still compile (non-breaking). New signature:
  `TouchPoint(Vector2 Position, TouchLocationState State, int Id = 0)`. `MonoGameRawInput` fills `Id`
  from `TouchLocation.Id` so a game can track the same finger across frames (required for dual-stick).

- **`IReadOnlyList<TouchPoint> Touches { get; }` on `InputManager`** — the active touches with their
  positions transformed into **virtual** coordinates (id + virtual position + state). Empty on
  desktop. This is what a game uses to implement independent multi-finger controls.

- **`Pinch` readonly struct** (new file `Pinch.cs`):
  `readonly record struct Pinch(bool Active, Vector2 Midpoint, float Distance, float Delta, float Scale)`
  where `Midpoint` is virtual-space, `Distance` is the current two-finger distance (virtual),
  `Delta` is the distance change this frame, and `Scale` is `currentDistance / previousDistance`
  (1.0 on the first pinch frame or when not pinching).

- **`bool TryGetPinch(out Pinch pinch)` on `InputManager`** — returns true while two or more touches
  are active, with the populated struct; false (and `default`) otherwise.

The existing `IsPinching` and `GetPinchDeltaIn(rect)` stay unchanged (Nullwake uses them). Internally
the pinch midpoint/distance are computed once per frame and shared.

### 3. Controller cursor (gamepad / keyboard-driven pointer)

- **Constructor gains `float cursorSpeed = 0`**: `InputManager(bool isMobile = false,
  ICoordinateTransform? transform = null, float cursorSpeed = 0)`. `0` disables the cursor (today's
  behavior exactly).

- **`Update` gains an optional `float dt = 0`**: `Update(RawInputState raw, bool isActive,
  float dt = 0)`. Hardpoint/Nullwake's existing 2-argument calls bind to the default and are
  unaffected.

- **Behavior** (only when `cursorSpeed > 0`, desktop, and `isActive`): if the mouse moved since last
  frame OR the left button is down, the pointer snaps to the mouse (current behavior). Otherwise the
  pointer integrates gamepad-0 left stick (x, −y) plus the arrow keys at `cursorSpeed * dt`, clamped
  to the transform's `VirtualBounds` (if any). It drives **`PointerPosition` only** — `IsPointerDown`,
  `IsPointerJustPressed/Released`, `PressOrigin`, and `IsTapIn` remain mouse/touch driven, and
  selection stays on the menu-navigation helpers. This matches exactly how SpaceGame's `VirtualCursor`
  is consumed (cursor for aim/hover; A/Enter to select). Mouse-move detection compares
  `raw.MousePosition` to the previous frame's.

SpaceGame then deletes `Inputs/VirtualCursor.cs`, constructs the `InputManager` with a `cursorSpeed`,
passes `dt` into `Update`, and reads `PointerPosition` for the cursor.

## Out of scope

- Any change to `KhaozEngine.Screens`, `.UI`, `.Ecs`.
- Synthesizing pointer-down/taps from a gamepad button (selection stays on menu-nav helpers).
- Touch handling on the desktop pointer path; `Touches` is simply empty there.

## Testing

All headless, via injected `RawInputState`:

- **Middle/right edges:** down / just-pressed / just-released fire only on the transition frame; both
  read false when `isActive` is false; false on mobile.
- **Multi-touch:** `Touches` surfaces each touch in virtual coordinates with its id (verify a
  non-identity transform is applied); empty on desktop.
- **Pinch:** `TryGetPinch` returns midpoint (virtual), distance, per-frame delta, and `Scale` ratio;
  false with fewer than two touches; first-frame `Scale == 1`.
- **Controller cursor:** with `cursorSpeed > 0` and a synthetic left-stick value + `dt`, the pointer
  drifts by `stick * cursorSpeed * dt` and clamps to `VirtualBounds`; a mouse move snaps the pointer
  back to the mouse; with `cursorSpeed == 0` the pointer ignores the stick entirely (regression guard
  for Hardpoint/Nullwake).
- **Non-regression:** the existing 32 tests stay green unchanged.

## Versioning & rollout

- Release as **0.2.0** (new features; additive). Pack to the local feed, tag `v0.2.0`, publish via CI.
- Hardpoint and Nullwake need no change; they adopt 0.2.0 only if/when they want the new APIs.
- SpaceGame bumps to 0.2.0, deletes `VirtualCursor`, and re-enables mobile dual-stick + true pinch
  (its own work, in its session).
