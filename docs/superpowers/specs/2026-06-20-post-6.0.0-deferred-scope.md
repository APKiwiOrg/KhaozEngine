# Post-6.0.0 deferred work + partials — scope

Date: 2026-06-20. Context: the 6.0.0 Primitives-leaf + Color-migration batch shipped (tag `v6.0.0`,
published). This is the backlog the audit surfaced that was consciously NOT done in that batch, plus the
two items 6.0.0 left intentionally partial. Each entry is scoped enough to hand to a future session.

Ranking key: Impact (HIGH/MED/LOW) = cost of leaving it; Effort (S < half-day / M < a day / L > a day).
"Breaking" = needs a major bump; otherwise additive (minor) or fix (patch).

## Status (updated 2026-06-20)
- SHIPPED in 6.1.0: D1 (preview stall), D2 (OverlayRenderer), D3 (music alloc), D6 (Gui consistency),
  D7 (Audio/Updates logging), P1 (ForEach query pooling), P2 ([ComponentId] policy doc).
- SHIPPED in 6.2.0: D4 (clip-space-Y via GpuClip) — Metal byte-identical; inverted-Y path correct-by-construction
  but NOT yet validated on non-Metal hardware.
- REMAINING: **D5** (device-lost/removed handling) and **D8** (central Platform OS-info seam, YAGNI). Both are
  genuine port-time work. D5 in particular cannot be done responsibly in a Metal-only environment — see its
  section for why (no device-removed detection or resource-recreation infrastructure exists, and it can't be
  validated without inducing device loss on non-Metal hardware).

## Deferred engine work

### D1. Render3DPreview.Capture stalls the GPU every frame — MED→HIGH, Effort M/L
`KhaozEngine.Render3D/Render3DPreview.cs` `Capture()` calls `_gd.WaitForIdle()` every frame. One inspector
panel is fine; several live previews (shop grid, unit roster) each force a full pipeline flush.
- Why now: Hardpoint already uses previews (enemy + tower panels); a preview-heavy screen stacks stalls.
- Approach: avoid the synchronous wait. Options, cheapest first: (a) double-buffer the readback so `Capture`
  returns last frame's texture (1-frame latency, zero stall); (b) batch all previews into one submit + a
  single shared fence; (c) add an async-readback/fence seam to `KhaozEngine.Gpu` and render previews into the
  frame's existing command list. (a) is likely enough and simplest.
- Breaking: option (a) changes timing (1-frame latency) — behavior note, not an API break. A new
  non-stalling capture method is additive (minor).
- Verify: headless assertion that N previews issue 1 (not N) `WaitForIdle`; visual check in Hardpoint;
  golden gate stays byte-identical for the still-frame case.

### D2. Unify Line/Fill/Billboard renderers into OverlayRenderer<TVertex> — MED, Effort M
`KhaozEngine.Render3D/Rendering/{LineRenderer,FillRenderer,BillboardRenderer}.cs` are near-identical: same
`{Position,(Uv),Color:Vector4}` vertex struct, 64-byte ViewProj UBO, resource layout/set, `EnsureCapacity`
(2x from 256), `Draw`, `Dispose`; they differ only in primitive topology (+ billboard UV). A 4th overlay
primitive = copy a 4th file.
- Approach: extract a generic `OverlayRenderer<TVertex>` base parameterized by vertex-layout description +
  topology + blend state; the three become thin configs. Keep the vertex structs `Vector4` (GPU layout).
- Breaking: no (internal renderers + internal types). Patch.
- Verify: golden gate (scene3d line/fill/billboard goldens) byte-identical. This is the lowest-risk item.

### D3. Music streaming per-frame allocation — LOW, Effort S
`KhaozEngine.Audio/OpenAlMusicBackend.cs` `Update()` allocates `new uint[1]` per processed buffer per frame
(and `new[]{_buffers[i]}` at track start) only to satisfy the span-less `SourceQueue`/`UnqueueBuffers`.
- Approach: two preallocated 1-element scratch arrays as fields (`_one` for queue/unqueue). Steady-state
  music becomes zero-alloc.
- Breaking: no. Patch.
- Verify: headless zero-alloc assertion over a streaming `Update` loop (if the backend is headless-testable).

### D4. Metal clip-space-Y flip is baked in (cross-platform correctness) — HIGH for port / zero now, Effort L
`Camera2D.cs` and `ModelRenderer.cs` carry TODOs: the y-down ortho / unflipped viewproj is correct for Metal
(the only backend exercised) but D3D11/Vulkan (`ClipSpaceYInverted` / `DepthRangeZeroToOne`) will render
inverted. The TODOs name the exact `GpuCapabilities` to read. This is the known cause of the (intentionally
ignored) red `cross-platform-gpu` CI — our byte-identical guarantee is Metal-verified only.
- Approach: derive the clip-space flip from `GpuCapabilities` at viewproj construction; generate/bless
  per-backend goldens. Pairs with D5 as "port hardening." Needs a non-Metal machine or working CI to validate.
- Breaking: no public API change; fixes (currently-broken) non-Metal rendering. Patch/minor.
- Verify: per-backend D3D11/Vulkan goldens green (requires CI/hardware).

### D5. No device-lost / device-removed handling — MED for Windows ship / LOW now, Effort L
Resize is handled (`RenderResources.Resize`, `IGpuDevice.ResizeSwapchain`) but there's no recreation path for
device-removed / driver reset / laptop GPU switch — it would crash unrecoverably on D3D11/Vulkan.
- Approach: device-lost detection + a resource-recreation pass in `KhaozEngine.Gpu` and the resource owners.
- Breaking: additive. Minor. Defer to the port.
- Verify: a simulated device-reset hook + recreation test.

### D6. Gui consistency minors (bundle) — LOW, Effort S each
- `Gui/PopupPanel.cs` private `DrawButton` rolls its own fill/hover/label instead of `GuiDraw.DrawButton`;
  route it through the shared path so popups inherit `GuiStyle` + press-origin invariant.
- Hardcoded `960x540` default viewport in `PopupPanel.cs`/`Tooltip.cs`; default to `Vector2.Zero` ("caller
  must set") or accept an `IDesignViewport` so a missed assignment fails loudly instead of mis-positioning.
- `Slider` drag-start semantics differ between retained (`Slider.cs`) and immediate (`GuiSurface.Slider`);
  add a shared `Pointer.IsDragStartIn(bounds)` and use in both.
- Breaking: the viewport-default change is mildly behavior-affecting; others are internal. Could be one small
  Gui-consistency minor release.

### D7. Silent catch blocks should log at Debug — LOW, Effort S
`AudioSystem` catch(Exception) flips the `_available` latch without logging (so audio going quiet is
invisible); `Updates` cleanup `catch {}` swallow temp/rollback failures silently. Add a one-line
`logger.Debug(...)` in each so field failures are diagnosable. No behavior change. Patch.

### D8. Central Platform OS-info seam — LOW, Effort M, SPECULATIVE (defer)
`OperatingSystem.Is*()` is scattered (Platform/ClipboardInterop, Updates/*, App). Only `App`
(`IAppDataEnvironment`) abstracts it. If a third subsystem needs OS branching, promote the OS flags into a
small shared `Platform` info type. YAGNI until a third consumer appears — do not build pre-emptively.

## Partials from the 6.0.0 batch (intentionally incomplete)

### P1. Pooling adoption is partial — MED, Effort M
E1 pooled only `EntityCommandBuffer`'s per-playback remap dictionary. The audit also flagged ECS
query-result list allocations and `UpdateService.cs new List<>(diff.FilesToDownload)`.
- Scope/caution: pooling is only safe where the buffer's lifetime is provably scoped (like the ECB dict). A
  pooled list a caller RETAINS across frames causes aliasing bugs. So: profile to confirm a real per-call
  alloc, and prefer "return a span over a reused internal buffer" over "return a pooled List" where the
  result escapes. Do not force pooling where lifetime escapes.
- Breaking: no. Patch. Verify with per-site allocation tests.

### P2. [ComponentId] is capability-only, not applied — Effort S (policy) / M+ (apply)
D2 shipped the `[ComponentId]` attribute + dup-key guard + `RegisterMigration` seam, but NO engine component
is annotated and NO migration is registered. Existing components are still rename-fragile (key by
`Type.FullName`).
- Caution: adding `[ComponentId]` to an ALREADY-SHIPPED component is itself a save-format break (old saves
  key by FullName) and requires a registered FullName->id migration. So it is not free.
- Recommended scope: (1) write the policy — new components get `[ComponentId]` from creation; existing ones
  only with a paired migration; (2) annotate any component that has no shipped saves yet; (3) defer the rest
  until a rename is actually needed (then add the migration with it). This is mostly a governance decision.

## Not deferred — deliberate decisions (recorded so they aren't re-litigated)
- Image-decode: only the StbImageSharp DECODE call was centralized in `ImageRgba`; the texture-create blocks
  in Render2DCore vs Scene3D stay separate (different return types Texture2D vs TextureHandle; a shared
  helper would force a bad cross-layer abstraction).
- `ModelVertex.Color` / vertex / UBO / instance structs stay `Vector4` (GPU memory layout, by the migration
  rule), even though `ModelVertex` is a public struct a consumer can construct.
- `WavSynth` noise output changed slightly (XorRng 24-bit mantissa); documented in the 6.0.0 CHANGELOG.
- `DesignViewport.cs` pre-divided scale scalars were left as-is (not routed through `ViewportMath`, which
  takes raw dimensions); a tiny optional cleanup, not worth its own change.
