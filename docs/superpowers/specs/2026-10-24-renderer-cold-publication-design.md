# Renderer cold publication amendment

This is the canonical implementation refinement for the remaining compiler collection and publication preparation in the [approved renderer baseline](../plans/2026-10-21-renderer-performance-baseline.md). It transcribes root rulings CP-1 through CP-6 from `.superpowers/sdd/2026-10-21-renderer-performance-baseline/cold-publication-rulings.md`. The [implementation plan](../plans/2026-10-24-renderer-cold-publication.md) owns task boundaries and verification. Source was checked at `e95154ffdd856269be54d0fea387689d6b974fa6`, including accepted Task11 and its corrections. This document makes no native measurement claim.

## 1. Fixed scope and authority

- Preserve the five scenes, twelve controls, manifest order, layouts, pacing, conditioning, warm-up and measured counts. A full unit has exactly 16,944 frames over 43 operations (one conditioning operation, 30 scene blocks and twelve controls). A pilot has nine operations. No second scene or extra Prepare/Record/Begin/Draw/Dispatch/Submit, calibration, invocation-query block, profiler, counter sampling or rendered frame belongs to collection.
- Preserve the 600/1,500-second pilot/full unit limits, 10,000 ms individual frame limit, 12/35-minute job caps and all original spend and approval gates. The existing post-authorization `coldStart` is the sole clock origin. No retry, fallback, best-attempt selection, dropped frame or automatic rerun follows any failure.
- Timed devices use compiler metadata off and runtime invocations off. Replay uses compiler metadata on and runtime invocations off. No process-global environment mutation is permitted. Retain the native creation gate, named-backend selection and no fallback.
- Keep the root cap at 268435456 bytes and JSON depth 32, including stamp padding. The root plus newly produced compiler sidecars also has a combined cap of 268435456 bytes. Keep `raw.format = metric-vectors/2` unchanged. Adopt `khaozengine.renderer-perf-report/2` and explicitly reject report/1.
- Resource counts mean current live counts at retained observations plus actual backend-maintained peak logical payload bytes. Do not add `PeakLiveResourceCount`. Diagnostic memory cannot raise the production peak.
- This amendment authorizes no runtime, build, native, timing, paid, stress or workflow run. Implementation and later native evidence remain separate root-owned work. Preserve staged 21.13.0. Recheck release history before eventual integration.

## 3. Truthful construction identity

Use `GpuDiagnosticDigest(string? Sha256, string Source, GpuDiagnosticStatus Status, string? Reason)` for every digest, including code generation. Available requires exactly 64 lowercase hexadecimal characters, nonempty encoding provenance and null Reason. Unsupported/Invalid requires null Sha256 and a nonempty cause. Every property is required even when nullable. Unknown, duplicated, missing, null-object, malformed or conflicting fields fail strict decoding.

An optional `IGpuPipelineConstructionDiagnostics.ConstructionIdentity` getter returns a detached, precomputed `GpuPipelineConstructionIdentity`. It performs no native read, reflection, hash, formatting or allocation. Backend pipeline owners produce it from the actual compiled stage bytes and resolved construction state. The existing optional `IGpuPipelineDiagnostics.ReadCompilerReport()` remains a cold operation and shares the same identity record. Neither changes mandatory pipeline/device obligations.

The identity contains PipelineSha256, SourceSha256, ShaderArtifactSha256, LayoutSha256, DiagnosticConfigurationSha256, CodeGenerationSha256, raw CompilerFlags, resolved local sizes and ordered stage identities. Each stage retains its original backend stage label, entry point, source digest, optional emitted-source digest and artifact digest. Stage sources use `glsl.utf8/1`, emitted MSL uses `msl.utf8/1`, and real artifacts use `spirv.bytes/1` or `dxbc.bytes/1`, all hashing exact nonempty bytes. EmittedSourceSha256 is null when no emitted-source evidence is retained, with that nullable property still required in JSON. Graphics stage order is vertex then fragment on Vulkan/Metal and vertex then pixel on D3D11. Compute has one stage. An empty compiled module is Invalid before hashing. MSL is source and cannot occupy an artifact slot. A sidecar checksum is never an artifact identity.

### Fixed encodings

New canonical encodings use a UTF-8 domain string followed by fields in declaration order. Encode strings as UInt32 little-endian UTF-8 byte length then exact bytes, arrays as UInt32 count then elements, enums as Int32 little-endian, booleans as one byte 0/1, nullable fields as presence byte then value, integers at their declared width, and floats as IEEE bits at their declared width. No culture formatting, platform newline, Unicode normalization, object hash, native address or source-hash sorting enters an encoding. Reject invalid UTF-16, unknown enums, nonfinite state or checked overflow. Hash exact bytes with SHA-256, rendered lowercase.

| Domain or wire schema | Ordered payload |
| --- | --- |
| `khaozengine.pipeline-stage-set/1` | Field selector `source` or `artifact`, stage count, then stage label, entry point and corresponding Available digest bytes as 32 bytes. Used for multi-stage aggregates. One stage keeps its actual byte digest. If any member is unavailable the aggregate is unavailable, retaining that cause and all companion stages |
| `khaozengine.pipeline-code-generation/1` | Backend, ordered backend-produced key/value options. Include actual frontend/cross-compiler pins/options, native compiler flags/profiles, precision and optimization. Reflection compiler-description text is observation metadata, not a replacement for these actual inputs. Exclude only observation choices. Do not parse or rewrite raw CompilerFlags to guess these values |
| `khaozengine.pipeline-diagnostic-configuration/1` | Full structured requested/effective configuration, including observation choices and code-generation options |
| `khaozengine.renderer-construction-recipe/1` | Pipeline kind, exact final shader sources/stages/entry points/local sizes, ordered layout elements, nullable graphics state in the field order in section 4, and production code-generation digest |
| `khaozengine.renderer-compiler-inventory/1` | Strict JSON sidecar with operation identities, factory events, source/layout tables, recipes, all pipeline occurrences, production witnesses and counts |
| `khaozengine.renderer-unit-failure/1` | Strict bounded early-failure JSON with admitted authorization, known actual facts, clock/stages, original failure and ordered cleanup errors. Unknown identity remains absent, never dummy T4 facts |

Coordinate the prerelease stage aggregate correction across VulkanShaderIdentity, D3D11PipelineDiagnostics and MetalPipelineDiagnostics. Their existing graphics aggregate algorithms differ. The new schema explicitly identifies the new encoding rather than relabeling old bytes. Retain per-stage real digests so a reader recomputes stage-to-aggregate relationships without exported binary modules. Existing backend resolved pipeline/layout encodings remain in their owners, with explicit provenance `vulkan.pipeline/1`, `vulkan.layout/1`, `d3d11.pipeline/1`, `d3d11.layout/1`, `metal.pipeline/1`, `metal.layout/1`. Preserve their BinaryWriter field order and resolved-state semantics. Their artifact input uses the new aggregate where applicable. Pin independent golden vectors in backend fixtures.

Missing correspondence identity invalidates the row. A malformed producer value is recorded as a bounded rejected-field cause and mapped to Invalid with null digest. Preserve valid companion identities and typed statistics. Native Boolean, Int64, UInt64 and finite Float64 remain exact, including UInt64.MaxValue. Do not route them through frame metric doubles. Complete optional Unsupported is allowed, Invalid or unattempted collection is not.

## 4. Actual capture and correspondence

A unit-scoped collector observes every shader, layout and pipeline factory attempt in conditioning, scenes and controls. Its operation ordinal comes from the frozen manifest expansion. Its creation ordinal is local to the operation and pipeline kind, independent of hashes. Stage is Cold, Warmup or Measured, with null frame index only for Cold. Preserve failed attempts, repeated creations, created-but-unused pipelines, all bound membership and the final specialized sources.

Copy each mutable value before forwarding the caller's original call exactly once. Layout elements preserve Name, Kind, Stages and Dynamic in order. Graphics state preserves BlendFactor, BlendAttachments, DepthStencil, Rasterizer, Topology, VertexLayouts (Stride, InstanceStepRate, ordered Name/Format elements), ordered resource layouts and Outputs (Depth, Colour, SampleCount). Compute preserves its shader and ordered layouts, using the shader's actual resolved local sizes. Record the native return and precomputed witness. Keep native objects on the existing recording path. Detached values survive shader/layout/pipeline disposal, operation teardown and timed-device disposal.

Perform harness recipe hashing and deduplication outside measured spans. Backend identity work already belonging to actual construction remains charged to that construction, including an invalidating first creation in a measured frame. Do not add hash work to the getter or bind path. Value-compare every digest collision. Deduplicate full recipes only, never source alone, and keep all occurrences and role keys `(operationOrdinal, kind, creationOrdinal)`. Independent wrapper forwarding counters, captured factory event/occurrence counts, unique recipes, replay attempts, root pipeline indices and bind membership must reconcile. A bind not associated with a captured successful native return invalidates inventory. No manual list of known renderers is the completeness oracle.

Replay fresh shader/layout/pipeline graphs only, in first-occurrence recipe order, after timed cleanup. Read each result before releasing its diagnostic graph. Compare every production occurrence associated with a recipe to its replay witness and report. Source, layout, pipeline, resolved local size, code-generation and primary-backend artifact identities must match exactly, including stage-to-aggregate checks. Configuration digests must both be valid but may differ only after structured effective-delta verification in section 5. Compiler nondeterminism refuses collection and returns evidence to root. It triggers no twins or retry.

Cross-run comparison joins logical occurrence keys. Allow candidate source/pipeline/artifact changes as informational only after each run proves its own correspondence. Require equal operation/role membership, layout, code-generation and effective settings. A split/merge in unique recipes is associated through occurrences, not positional unique-list indices.

First creation during a measured span stays in that frame's raw CPU/allocation/resource-creation evidence and refuses steady-state promotion. No hidden capacity growth, subtraction of observer cost or moving it into warm-up. Any no-growth or zero-allocation claim requires an isolated allocation-region test including this observer. Bind-path membership uses preallocated state, not report reads.

## 5. Immutable instance settings

Introduce the optional provider/context contracts named in the plan. Backend-owned immutable settings resolve environment defaults once, before production creation. `WithDiagnostics(true,false)` copies only diagnostic requests and retains all frozen adapter, validation, compiler, cache, recording, frames-in-flight and drain choices. Existing ordinary calls retain documented defaults. The harness rejects contradictory approved-environment diagnostic switches and explicitly supplies `(false,false)` for production. Neither creation nor per-shader compilation on this explicit route re-reads those switches.

Keep requested choices separately from actual configuration. Actual configuration has Backend, AdapterKey, Driver, Requested, CompilerMetadataEnabled, RuntimeInvocationsEnabled, DebugLayerEnabled, ValidationEnabled, PipelineStatisticsSupported, PipelineExecutableFeatureEnabled, PipelineCaptureFlags, ordered CodeGenerationOptions and ordered ObservationOptions. AdapterKey is the selected native adapter's stable key (Vulkan device UUID or D3D adapter LUID), not its display name alone. All keys are unique and canonical ordinal sorted. Actual options are backend-produced and include compilation cache provenance without treating a cache file as the produced artifact.

Production admission independently verifies actual metadata/invocation false, validation/debug off, Vulkan flags zero, and the existing native/T4/timestamp requirements. Diagnostic admission compares adapter key, driver, code-generation and all other effective settings without running a second calibration. Allowed effective deltas are compiler metadata false to true, Vulkan executable feature enablement when actually supported and the corresponding capture-statistics bit. Runtime invocations, debug, validation, recording mode, adapter and code-generation options never differ. Reflection compiler description may enrich observation metadata. Code generation on both devices comes from the actual frontend pins/options and native flags/profiles retained before reflection, without inferring a production compiler version from diagnostic-only text. A digest difference alone is never a waiver.

Genuine optional extension/feature absence yields complete Unsupported with its cause and valid required identities. Supported routes that omit required capture, reflection errors, disposed handles, incomplete enumeration or missing identities are Invalid. Unsupported optional statistics or Metal native artifact absence do not alone invalidate timing. A provider lacking the optional settings path cannot satisfy the collector and is refused without environment toggles or backend fallback.

## 6. Explicit count and byte admission

These are conservative refusal limits, not certified native workload maxima. All counts and byte arithmetic are checked before copying, allocating native output storage, reading strings or starting another report. Reject one beyond each bound. Existing recorder capacity 4096 is not reused as a global compiler bound.

| Owner | Fixed bound and rationale |
| --- | --- |
| Construction collector | At most 43 operations, 256 pipeline attempts per operation (both kinds combined), 1024 total factory attempts per operation and therefore 11008 pipeline/44032 factory attempts per full unit. Pilot uses its actual nine operations, not a padded workload. 256 is an admission envelope, not a source-derived pipeline count |
| Retained graphs | 32 layout sets per pipeline, 128 elements per set, 32 vertex streams, 64 elements per stream, eight color/blend attachments, 1024 UTF-8 bytes per name, 1048576 UTF-8 bytes per shader stage, 1024 unique recipes. Retained logical encoding is at most 67108864 bytes, partitioned into 33554432 source bytes, 16777216 descriptor bytes and 16777216 event/occurrence/witness bytes. Check before deep copy, include every repeated occurrence. Strings are immutable but count their full UTF-8 length before retention. Managed representation overhead is observed memory, not claimed equal to encoded bytes |
| Primary backend report | Vulkan retains its 64 executables, 256 statistics per executable, four bounded API enumeration attempts and 256-byte native name/description arrays. Budget 4096 encoded bytes per statistic, 8192 per executable excluding statistics, 262144 per identity/header. `262144 + 64*8192 + 64*256*4096 = 67895296`, below a 75497472-byte reservation. D3D has at most two stages and the existing 30 fixed reflection statistics each, giving `262144 + 2*8192 + 60*4096 = 524288`, below a 1048576-byte reservation. | Effective option tables | At most 64 entries each in CodeGenerationOptions and ObservationOptions, ordinal-unique keys at most 256 UTF-8 bytes and values at most 4096 bytes. Bound before retention. | Backend text | Vulkan decodes only the existing 256-byte native arrays and validates UTF-8. The plan supplies a bounded reflection seam because the current managed Description can marshal Creator before a later length check |
| Completion reserve | Keep 16777216 bytes free for collection completeness/error rows, cleanup failures, references and accounting, including both 32-byte slots. | Publication | Root bytes plus inventory/failure compiler sidecars at most 268435456, each structured compiler file depth at most 32. Reserve the selected backend's complete maximum before calling its report reader, then debit actual encoded output. All compiler evidence has explicit kind `compiler-inventory` or `compiler-failure`. Pipeline reports stay in the root. Compiled module export is not introduced. Noncompiler sidecars retain existing limits and are also verified. The aggregate is independently checked from final actual file lengths, not just reservation estimates. Maximum envelopes are not meant to be simultaneously admissible. Failure to fit is an expected refusal, not permission to enlarge limits.

Capacity refusal freezes collection, retains frame evidence and reports admitted, omitted and unattempted counts and the exact first capacity cause. The factory call that encountered capture exhaustion still forwards once. Stop the workload at the next safe frame/operation boundary. Preserve native exceptions as OriginalFailure if the forwarded call itself failed, then append the observer failure. Emergency preallocated counters record calls that could not be retained after exhaustion. Such evidence is explicitly incomplete and never promotes.

Reserve complete bounded causes before new optional work. Every release is still attempted even after reserve exhaustion or deadline. Retain all exception objects in order for the caller. If error text itself exceeds the remaining serialized reserve, mark failure evidence incomplete with omitted-error count and byte requirement, preserve the first original cause and already admitted records, and return the actual exception chain to root. Never silently clip a vendor field or certify such a file as complete. Abrupt process kill cannot promise even this in-memory recovery.

Metal remains a shared typed-identity/codec correctness case, not a primary unit. Its counter metadata has 64 sets/256 counters per set in current source. Bound native NSString byte length before conversion in any bounded report route, retain actual names or refuse. The primary Vulkan/D3D reservations do not establish a Metal output maximum or authorize Metal timing.

## 7. One lifecycle and honest failure

The unit owner executes these stages in order under one `RendererPerfUnitBudget` (clock, ColdStart, absolute Deadline, CancellationToken).

1. Retain admitted authorization and clock origin, resolve settings, construct/admit production device, execute only scheduled operations and capture actual construction.
2. Finish all session cleanup, retain exactly one `unit-final` production memory observation with operation `unit`, null frame index, then dispose production context. Extend memory validation by exactly this one observation. Keep backend count domains, payload/staging overlap and unsupported residency/budget intact.
3. Freeze immutable inventory, canonicalize/deduplicate and check budget. Create/admit diagnostic device, replay/read each admitted recipe, release graphs and dispose diagnostic context. No replay starts after a workload failure.
4. Prepare registered sidecars, serialize/write the provisional final JSON and Markdown, then independently reopen and verify the complete directory including the written root and all associations. Sample completion only after that verification, stamp the two accounting slots and check deadline. The stamp changes only the reserved accounting bytes, not identities or sidecar references. Both contexts and all native graph objects are disposed before Completed can be certified.

Check cancellation/deadline before and after every safe native creation/read and each bounded file chunk/transition. No new item starts after expiry/cancellation. Native compiler/query/disposal calls are not promised interruptible. Cleanup consumes time/cost even after expiry and preserves every failure in release order. Use reverse dependency order for graphs. After a workload/compiler failure freeze the subset, mark pending rows Incomplete, and do not compile more to fill optional evidence.

The first workload/compiler failure remains OriginalFailure. Later cleanup/publication failures append without replacing it. Cancellation and DeadlineExceeded are distinct collection states. Invalid compiler evidence, inventory disagreement, hot creation or a failed/late final makes promotion false. Complete Unsupported optional evidence does not. Before trustworthy run identity exists, write only the bounded failure sidecar with admitted authorization and actual known facts. Do not fabricate a normal report. Preserve existing partial recovery and failed-final correction, with no automatic rerun.

## 8. Registered artifacts and certification

Actual producers register expected sidecars by kind, schema, safe relative path, exact length, SHA256 and decoded counts. Register manifest/source corpus/control definitions/recipes/frozen layouts/native admission/work models through their existing owners as well. Directory enumeration cannot invent evidence. Unregistered files cannot substitute for expected files. Strict readers reject duplicate/unknown/missing fields and report/1 with an unsupported-version cause. Preserve old files without migration.

The directory verifier resolves every path beneath the evidence root, rejects rooted/escaped/dot/empty components, duplicate paths and aliases, and refuses symbolic-link/reparse-point traversal. Reopen expected regular files with bounded streams. Verify nonempty required files, exact length, streamed SHA256, strict schema, unit/manifest/workload identity and decoded totals for factory attempts, occurrences, unique recipes, result associations, executables and statistics. Recompute stage aggregates and recipe digests from retained values. Verify every occurrence's production witness against its associated replay result, effective configuration deltas and membership. Independently sum actual root plus compiler-sidecar lengths using checked Int64 arithmetic. Refuse missing, altered, wrong-identity, duplicate or empty-required sidecars before certification.

Live verification precedes the completion instant. Offline/workflow verification repeats integrity against the received directory to detect changed uploads. `Parse(bytes)` remains structural decoding only and cannot yield verified-artifact status. Directory-aware analysis and workflow acceptance must use the same managed verifier. Comparison of unverified data gives no regression verdict.

The decisive synthetic size proof extends the existing recorder-built 16944-frame fixture with nonempty actual-shaped graphics/compute inventories, repeated occurrences, all source/layout/state encodings, production/replay/stage witnesses, raw typed statistics, complete Unsupported and Invalid examples, sidecars, errors and final stamp padding. Independently decode counts and measure each real file's length. Check exact and one-over boundaries, malformed files and partial correction. A valid fixture with complete optional Unsupported can be promotion-eligible. Its Invalid variant must refuse promotion while retaining raw frame/scalar evidence. Fake data establishes format/accounting, not native completeness.

## 9. Remaining proof limits

Headless fixtures can prove forwarding, immutable capture, canonical encodings, logical role matching, bounded refusal, lifecycle ordering and strict file verification. They cannot prove real primary-backend compilation correspondence, complete native workload admission, actual vendor strings/statistics, combined native payload size, cold-stage elapsed cost or unchanged-deadline acceptance. Root must inspect those on separately authorized hardware. A failure returns its exact workload/artifact/byte/clock evidence. No larger cap, extra frame, relaxed hash check or rerun is implied.
